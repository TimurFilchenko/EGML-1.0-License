## Code of Conduct

By participating in this project, you agree to be respectful and
constructive. Disagreements are welcome; hostility is not.

---

## How to Contribute

1. **Fork** the repository
2. **Create a branch** for your changes:
   ```bash
   git checkout -b feature/my-idea
```

3. Make your changes
4. Commit with a clear message:
   ```bash
   git commit -m "Add: description of change"
   ```
5. Push to your fork:
   ```bash
   git push origin feature/my-idea
   ```
6. Open a Pull Request against the main branch

---

What You Can Propose

· Wording improvements and clarifications
· Typo fixes and grammatical corrections
· New license versions (v1.1, v2.0) with clear reasoning
· Translations into other languages
· Additional documentation and examples
· Improvements to README, FAQ, or other files

---

What You Cannot Do

· Change the core meaning of the license without prior discussion
· Add new restrictions that were not present before
· Remove existing permissions
· Introduce legal language that has not been reviewed
· Submit changes that violate the spirit of EMGL

---

Pull Request Process

1. Ensure your changes are consistent with the existing style
2. Update the CHANGELOG.md if your change is significant
3. Reference any related issues in your PR description
4. Be patient — reviews may take time
5. Be open to feedback and revisions

---

Style Guide

· Use clear, concise English
· Follow the existing formatting conventions
· Use Markdown consistently
· Keep line lengths reasonable (80–100 characters where possible)
· Prefer simple sentences over complex ones

---

Questions

If you have questions about contributing, open an issue in the
repository or contact the Author.

---

Thank you for helping improve EMGL.
